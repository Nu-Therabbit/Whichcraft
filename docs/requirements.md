# Whichcraft — ความต้องการรุ่นแรก

เอกสารนี้รวมเป้าหมาย ขอบเขต ผลสำรวจเครื่อง ข้อเท็จจริงที่ค้นมา และผลการสัมภาษณ์ คำศัพท์อยู่ใน [CONTEXT.md](../CONTEXT.md) และการตัดสินใจระยะยาวอยู่ใน [docs/adr/](adr/)

อัปเดต: 23 ตุลาคม 2026 (Asia/Bangkok)

**ชื่อโปรเจกต์:** Whichcraft มาจาก `which` + witchcraft เดิมชื่อ Switchyard แต่เปลี่ยน เพราะชนกับ NVIDIA-NeMo/Switchyard ซึ่งเป็นเครื่องมือของนักพัฒนาเหมือนกันและมีผู้ใช้มาก ส่วนชื่อ npm และ crates.io ก็มีคนใช้แล้ว ชื่อ Whichcraft ยังว่างทั้งใน npm และ winget บน GitHub มีไลบรารี Python ชื่อเดียวกัน (cookiecutter/whichcraft) แต่เป็นงานคนละประเภท ไฟล์ใน `spikes/` ยังมีพาธ `E:\Dev\Switchyard` อยู่ เพราะบันทึกตามที่รันจริงในตอนนั้น

**สถานะ:** ผู้ใช้ยืนยันความเข้าใจร่วมกันของขอบเขตรุ่นแรกแล้วเมื่อ 23 ตุลาคม 2026 งานพิสูจน์ทั้ง 7 ข้อในส่วนที่ 7 ทำครบแล้วในวันเดียวกัน ไม่มีข้อใดทำให้ต้องเปลี่ยน ADR แต่หลายข้อผ่านโดยมีเงื่อนไขที่ต้องนำไปออกแบบ ยังไม่ได้ fork Envarly เป็นโปรเจกต์จริงและยังไม่ได้เริ่มพัฒนา

## 1. เป้าหมาย

สร้างแอป GUI บน Windows สำหรับจัดการเครื่องมือพัฒนาหลายชนิด ผู้ใช้ทำได้ดังนี้
- ดูการติดตั้งของแต่ละเวอร์ชัน
- ติดตั้งหรือถอนการติดตั้ง
- เลือกการติดตั้งที่ต้องการใช้
- ตรวจพาธและตัวแปรที่จะเปลี่ยน
- Apply หรือย้อนกลับ

เครื่องมือพัฒนาในที่นี้ไม่ได้มีแค่ Java และ SDK แต่รวม runtime, build tool และ Git ด้วย

## 2. ขอบเขตรุ่นแรก

### ทั่วไป

- เป็น GUI บน Windows เริ่มใช้ส่วนตัวบนเครื่องนี้ แต่เผื่อเผยแพร่ภายหลัง
- สลับการติดตั้งของ Java, Node.js, Python, Go, Flutter และ Git ได้
- Android SDK/NDK และ MSVC แสดงข้อมูลอย่างเดียว
- ดาวน์โหลด ติดตั้ง อัปเดต และถอนได้ โดยใช้ mise เวอร์ชันที่ pin ไว้ ซึ่งแอปดาวน์โหลดเมื่อผู้ใช้สั่งติดตั้งครั้งแรก และตรวจ SHA256 ก่อนใช้ ([ADR-0002](adr/0002-envarly-base-with-bundled-mise.md))
  - ติดตั้งได้: Java (เฉพาะ Temurin), Node, Python, Go และ Flutter
  - Git สลับได้อย่างเดียว
- ขั้นตอนหลัก: ตรวจหา → เลือกเวอร์ชัน → แสดงการเปลี่ยนพาธ → Apply → ย้อนกลับ
- เลือกค่าเริ่มต้นของ Windows และเปิด Terminal ใหม่จากแอป การแยกเวอร์ชันต่อโปรเจกต์อยู่นอกขอบเขต ([ADR-0001](adr/0001-windows-default-before-per-project.md))

### การเขียน environment

- เขียนพาธของการติดตั้งลง environment โดยตรง ไม่ใช้ shims ([ADR-0003](adr/0003-write-paths-directly-not-shims.md))
- แก้ System environment ได้เมื่อจำเป็น ต้องขอ UAC ทุกครั้ง แสดง diff และเตือนว่ากระทบผู้ใช้ทุกคนในเครื่อง
- พาธที่อยู่ในพื้นที่ของผู้ใช้ (เช่น `%LOCALAPPDATA%`) เขียนลง User เท่านั้น ถ้ามีรายการใน System บังการติดตั้งที่เลือกอยู่ ให้เสนอเอารายการนั้นออกจาก System แทน ([ADR-0004](adr/0004-user-scope-paths-only-in-user-environment.md))
- แสดงการติดตั้งที่มีผลจริงเสมอ คือค่าที่คำนวณจาก registry ก่อน shell โหลด profile ถ้าไม่ตรงกับการเลือกให้ทำเครื่องหมายไว้
- มีปุ่ม "ตรวจใน shell" สำหรับ PowerShell 7, Windows PowerShell 5.1 และ cmd ปุ่มนี้รัน shell พร้อม profile และแสดงความต่างถ้าผลใน shell ไม่ตรงกับการติดตั้งที่มีผลจริง
- Undo ย้อนเฉพาะสิ่งที่แอปเปลี่ยน
  - ถ้ารายการเดียวกันถูกโปรแกรมอื่นแก้ทับ ให้แจ้ง conflict และให้ผู้ใช้เลือก
  - สิ่งที่โปรแกรมอื่นเพิ่มเข้ามา ให้คงไว้
- เสนอให้ลบรายการ PATH ที่ซ้ำหรือชี้ไปพาธที่ไม่มีอยู่ ผ่าน diff และ Undo แบบเดียวกับการ Apply ไม่ลบอัตโนมัติ รายการที่ใช้ตัวแปร เช่น `%JAVA_HOME%\bin` ต้องขยายตัวแปรก่อนตัดสินว่าโฟลเดอร์ไม่มีอยู่จริง
- Python สลับเฉพาะ `python` ใน PATH ส่วน `py` launcher และ Microsoft Store stub แสดงเป็นข้อมูลแยก
- Terminal ตั้งค่าได้ ค่าเริ่มต้นเป็น Windows Terminal และต้องเปิดด้วย environment ที่คำนวณใหม่จาก registry

### การติดตั้งภายนอก

- อ้างอิงไฟล์ที่ตำแหน่งเดิม ไม่ย้ายเข้าโฟลเดอร์ของแอป ตัวติดตั้งหรือเครื่องมือเดิมยังเป็นเจ้าของไฟล์
- ถ้าโฟลเดอร์ถูกย้ายหรือลบ ให้แสดงเป็นการติดตั้งที่ใช้งานไม่ได้ ไม่สรุปเองว่าถูกถอนแล้ว
- การถอน
  - ถ้ามี uninstaller ลงทะเบียนไว้ ให้เปิดแบบปกติ (ไม่ silent) แล้วสแกนใหม่เพื่อตรวจว่าโฟลเดอร์หายจริง
    - ถ้าเป็น MSI (`WindowsInstaller=1`) ให้เรียก `msiexec /x {ProductCode}` เอง เพราะ UninstallString มักเป็น `/I` ซึ่งเปิดหน้า Modify
    - ถ้ารายการมีแต่ไม่มี UninstallString (เช่น Android Studio จาก JetBrains Toolbox) ให้ถือว่ามีเครื่องมืออื่นดูแลอยู่ และไม่เสนอให้ลบเป็นโฟลเดอร์ล้วน
  - ถ้าเป็นโฟลเดอร์ล้วน ให้ย้ายไป Recycle Bin หลังผู้ใช้ยืนยัน โดยแสดงพาธและขนาด และต้องผ่านเงื่อนไขทุกข้อด้านล่าง ถ้าไม่ผ่านข้อใด ให้ปฏิเสธ แสดงเหตุผล และมีปุ่มเปิดโฟลเดอร์ให้ผู้ใช้ลบเอง
    1. โฟลเดอร์เป็นรากการติดตั้งของเครื่องมือนั้น
       - Java: `release` + `bin\java.exe`
       - Node: `node.exe` อยู่ที่ราก
       - Go: `VERSION` + `bin\go.exe`
       - Flutter: `bin\flutter.bat` + `bin\cache\flutter.version.json` (รุ่นใหม่ไม่มีไฟล์ `version` ที่รากแล้ว)
       - Python: `python.exe` + `Lib`
    2. ไม่ใช่รากไดรฟ์ โฟลเดอร์โปรไฟล์ผู้ใช้ โฟลเดอร์ค้นหา โฟลเดอร์ Windows หรือราก `Program Files`
    3. ข้างในไม่มีการติดตั้งอื่นที่แอปตรวจพบ
    4. ไม่ใช่ junction หรือ symlink (ถ้าเป็น ให้แสดงพาธปลายทาง)
    5. ไม่มี process ใช้อยู่

### การติดตั้งที่แอปจัดการ

- ที่เก็บ: ถามตอนติดตั้งครั้งแรก ค่าเริ่มต้นคือ `%LOCALAPPDATA%\Whichcraft\installs` เปลี่ยนภายหลังได้ แต่มีผลกับการติดตั้งใหม่เท่านั้น
- การติดตั้งแต่ละตัวบันทึกที่เก็บของตัวเอง ตอนถอนหรือดูรายการ แอปเรียก mise ด้วยโฟลเดอร์ข้อมูลของที่เก็บนั้น ที่เก็บเก่ายังใช้งานได้จนกว่าจะว่าง
- การอัปเดต: ติดตั้งเวอร์ชันใหม่ในสายเดียวกัน สลับไปใช้ แล้วเสนอให้ถอนตัวเก่า ไม่เขียนทับ

### การถอนตัวที่ใช้อยู่ (ทั้งสองประเภท)

- ถ้าการติดตั้งนั้นเป็นการเลือกหรือการติดตั้งที่มีผลจริง ผู้ใช้ต้องเลือกตัวแทนในหน้าถอน แอปจะ Apply การสลับก่อนแล้วจึงถอน
- แสดงโปรไฟล์ที่อ้างถึงการติดตั้งนั้น และเสนอให้เปลี่ยนไปอ้างตัวแทน (ติ๊กไว้ก่อน)
- ถ้ามี process รันจากโฟลเดอร์ของการติดตั้งนั้น ให้แสดงรายชื่อ และไม่ให้ถอนจนกว่าจะปิดหมด แอปไม่ kill เอง
  - วิธีตรวจ: ใช้ Restart Manager กับไฟล์หลักของการติดตั้ง แล้วลองเปลี่ยนชื่อโฟลเดอร์ไปและกลับ เพื่อจับ shell ที่ cd ค้างอยู่ ซึ่ง Restart Manager มองไม่เห็น

### เมื่อล้มเหลวหรือถูกยกเลิกกลางทาง

แอปจดบันทึกขั้นตอนก่อนเริ่มทุกครั้ง และเมื่อจบต้องอยู่ในสถานะที่รู้แน่ชัด แต่ละกรณีด้านล่างเป็นเกณฑ์ทดสอบรับงานด้วย

| กรณี | ผลที่ต้องได้ |
|---|---|
| ผู้ใช้กดยกเลิก UAC ระหว่าง Apply ที่แก้ทั้ง User และ System | ยกเลิกทั้งชุด ไม่เขียนส่วน User ด้วย |
| เขียน registry สำเร็จบางรายการ | ย้อนรายการที่เขียนไปแล้ว ถ้าย้อนไม่ได้ให้รายงานทีละรายการ |
| ผู้ใช้กดยกเลิกใน uninstaller หลังสลับไปตัวแทนแล้ว | การสลับคงอยู่ แอปสแกนใหม่ การติดตั้งเดิมยังอยู่และเลือกกลับได้ |
| uninstaller จบแล้วแต่โฟลเดอร์ยังเหลืออยู่ | แสดงว่าถอนไม่ครบ แล้วเสนอให้ย้ายไป Recycle Bin ตามเงื่อนไขของโฟลเดอร์ล้วน |
| ดาวน์โหลดหรือติดตั้งผ่าน mise ล้มเหลว | ลบไฟล์ที่ค้างในที่เก็บ และไม่แตะ environment |
| แอปปิดหรือ crash กลางการสลับ | เปิดครั้งถัดไป ตรวจบันทึกที่ค้าง แสดงสถานะจริง แล้วเสนอให้ทำต่อหรือย้อนกลับ |

### โปรไฟล์

- สร้างโปรไฟล์ที่ตั้งชื่อได้ และเลือกการติดตั้งเป็นรายเครื่องมือ
- โปรไฟล์อาจระบุแค่บางเครื่องมือ เครื่องมือที่ไม่ได้ระบุคงค่าเดิม ตัวอย่าง:
  - โปรไฟล์ A เลือก Java 17 และ Node 20
  - ต่อมา Apply โปรไฟล์ B ที่เลือกแค่ Java 21
  - ผล: Java เปลี่ยนเป็น 21 แต่ Node ยังคงค่าปัจจุบัน
- อ้างถึงการติดตั้งด้วยผู้จำหน่ายและเวอร์ชันเต็ม ถ้าตรงหลายการติดตั้ง ให้ใช้ตัวที่จำไว้ก่อน
- ถ้ามีการติดตั้งใดในโปรไฟล์ใช้งานไม่ได้ ให้ยกเลิกทั้งชุดโดยไม่เขียนอะไร แล้วแสดงรายการที่ต้องแก้ ถ้าตัวที่หายติดตั้งผ่านแอปได้ ให้มีปุ่ม "ติดตั้งตัวที่หาย แล้ว Apply ต่อ" ซึ่งแสดงขนาดดาวน์โหลดและให้ยืนยันก่อน
- ไม่มีสถานะ "โปรไฟล์ที่ใช้อยู่" แต่แสดงว่าแต่ละโปรไฟล์ตรงกับการติดตั้งที่มีผลจริงหรือไม่
- ยังไม่มีการส่งออกและนำเข้าโปรไฟล์ในรุ่นแรก

### การค้นหา

- ค้นหาอัตโนมัติจาก PATH, Registry และโฟลเดอร์มาตรฐาน
- ผู้ใช้เพิ่มโฟลเดอร์ค้นหาเองได้ เช่น `E:\Dev`
- ไม่สแกนทุกไดรฟ์อัตโนมัติ

### ประเด็นพาธที่พบ

- JAVA_HOME และพาธ Java ระดับ User ชี้ไปที่ Temurin 21.0.11 แม้จะมี JDK ตัวอื่นอยู่
- Node.js, Go และ Git มีพาธระดับ Machine ซึ่งอยู่ก่อน User PATH ใน process ที่ตรวจ การเพิ่มพาธแค่ระดับ User จึงไม่รับประกันว่าจะเปลี่ยนตัวที่ถูกเรียกใช้จริง
- Android SDK อยู่ที่ %USERPROFILE%\AppData\Local\Android\Sdk แต่ไม่พบ ANDROID_HOME หรือ ANDROID_SDK_ROOT ในขอบเขตที่ตรวจ โปรเจกต์ Android ที่อ่านใช้ local.properties ชี้พาธโดยตรง
- Gradle หลายเวอร์ชันที่พบเป็น cache ของ Wrapper ไม่ใช่หลักฐานว่ามี Gradle ส่วนกลางที่เรียกผ่าน PATH ได้
- %USERPROFILE%\go\bin ซ้ำ 3 รายการใน User PATH
- มีพาธของ Ollama ที่โฟลเดอร์ไม่มีอยู่แล้ว
- ตอนตรวจไม่พบ mise, vfox, nvm, fnm หรือ Scoop ใน PATH

## 4. ข้อเท็จจริงเรื่อง mise บน Windows

ค้นจากเอกสารและ source ของ mise ในเดือนตุลาคม 2026 ข้อที่มีคำว่า **ยังไม่ยืนยัน** อนุมานจากเอกสารหรือ source

**ผลทดลองบนเครื่องนี้ (งานพิสูจน์ข้อ 3, 23 ต.ค. 2026)** รายละเอียดอยู่ใน [spikes/03-mise/RESULT.md](../spikes/03-mise/RESULT.md)
- mise v2026.10.17 ติดตั้ง รันจากพาธตรง และถอน Temurin, Node, Python และ Go ได้ครบ
- Flutter ผ่าน `http:flutter` ล้มเหลว เพราะ zip มีไฟล์ read-only ต้องใช้ `vfox:jdx/vfox-flutter` แทน
- ที่เก็บ A/B แยกกันได้จริง
- `mise ls --json` ไม่มีผู้จำหน่าย และชื่อเวอร์ชันของ Java ไม่ตรงกับเวอร์ชันจริง แอปต้องอ่านข้อมูลนี้จากไฟล์ในการติดตั้งเอง
- mise สร้าง junction สำหรับชื่อย่อเวอร์ชัน ตัวค้นหาต้องข้าม junction เหล่านี้
- mise.exe ของ Windows มีขนาด 230 MB (zip 77 MB) ใหญ่ขึ้นจาก 16 MB (zip) ใน v2025.7.11 จึงเปลี่ยนเป็นโหลดตอนใช้ครั้งแรกแทนการพกมาใน installer (Q31)

ข้อเท็จจริงจากเอกสาร (ก่อนทดลอง):

- **ติดตั้งได้บน Windows**
  - Java: `core:java` ค่าเริ่มต้นคือ Temurin ยังไม่ยืนยันว่าทดสอบบน Windows
  - Node: `core:node` ตรวจ SHASUMS256
  - Python: `core:python` ใช้ build สำเร็จรูปของ python-build-standalone เท่านั้น
  - Go: `core:go` ตั้ง GOROOT ให้
  - Flutter: `http:flutter` เฉพาะ x64
- **Git for Windows ไม่มีใน registry ของ mise** ส่วนการใช้ backend `github:` หรือ `http:` กับ PortableGit ยังไม่ยืนยัน
- **asdf plugins ใช้บน Windows แบบ native ไม่ได้** backend ที่ใช้ได้คือ core, aqua, github, http, npm และ vfox
- **ใช้การติดตั้งเดิมได้:** มี `mise link <tool@version> <path>` และสำหรับ Java มี `path =` ด้วย ยังไม่ยืนยันว่าบน Windows ต้องใช้สิทธิ์ admin หรือ Developer Mode ไหม (Whichcraft ไม่ใช้ความสามารถนี้ตาม ADR-0003)
- **`mise uninstall`** ลบโฟลเดอร์ของการติดตั้ง ส่วนการติดตั้งที่ลิงก์ไว้น่าจะถูกลบแค่ลิงก์ ยังไม่ยืนยัน ต้องลองด้วย `--dry-run`
- **mise ไม่เขียน JAVA_HOME หรือ PATH ถาวรลง registry** (ยังไม่ยืนยัน) โปรแกรมนอก shell เห็นเวอร์ชันที่เลือกผ่าน shims เท่านั้น
- **ข้อจำกัดของ Windows ที่รู้แล้ว**
  - cmd.exe ทิ้ง PATH ทั้งหมดถ้ายาวเกิน 8191 ตัวอักษร
  - shim แบบ `.cmd` ทำให้ editor บางตัวเจอ `spawn EINVAL`
- **ผลลัพธ์ที่แอปอ่านได้:** `mise ls --json` สำหรับการติดตั้งในเครื่อง และ `mise ls-remote <tool> --json` สำหรับเวอร์ชันที่ดาวน์โหลดได้ (ไม่มีเอกสารบอกโครงสร้างของ field)

## 6. ข้อจำกัดทางเทคนิค

1. **User PATH กับ System PATH:** ต้องทดสอบว่าตัวไหนชนะการค้นหาคำสั่งจริง ไม่ใช่ดูแค่ว่ามีพาธของเวอร์ชันที่เลือกอยู่ในรายการ
2. **โปรแกรมที่เปิดอยู่:** การเปลี่ยน environment ถาวรหรือการ broadcast ไม่ได้เปลี่ยน environment ของ process ที่เปิดอยู่แล้ว
3. **Terminal ใหม่จากแอป:** ต้องได้ environment ที่คำนวณใหม่ ไม่ใช่ค่าเก่าที่ค้างอยู่ใน process ของแอป
4. **IDE และ build daemon:** IDE ที่กำหนด SDK เอง และ process ที่รันอยู่ อาจไม่เปลี่ยนตามค่าเริ่มต้นของ Windows แอปต้องอธิบายข้อจำกัดนี้ให้เข้าใจได้
5. **Rollback ของ Envarly:** เอกสารกับ source ที่เว็บแคชไว้ให้รายละเอียดไม่ตรงกัน ต้อง pin commit แล้วตรวจและทดสอบเอง ห้ามสรุปว่ามี transaction หรือ rollback ที่ไม่ชนกันพร้อมใช้แล้ว
6. **Build Envarly:** เอกสารระบุ Node 22 และ Rust stable ต้องตรวจ dependency และ WebView2 ของ commit ที่เลือก แม้เครื่องจะมี Node, Rust และ C++ Build Tools อยู่แล้ว

## 7. งานพิสูจน์ก่อนพัฒนา

ทำบนเครื่องนี้ทั้งหมด ข้อ 1, 3 และ 4 สำคัญที่สุด ถ้าข้อใดไม่ผ่าน ให้ทบทวน ADR-0002 หรือ ADR-0003 ข้อ 1 และ 4 แก้ PATH จริง ต้องสำรองค่าเดิมก่อน

1. **PATH — ผ่าน (23 ต.ค. 2026):** Node 22 ที่อยู่หน้าสุดของ User PATH ยังแพ้ Node 24 ใน System PATH พอเอารายการนั้นออกจาก System ตัวที่เลือกจึงมีผล ดู [RESULT](../spikes/01-path/RESULT.md) — เกณฑ์: เพิ่ม Node ตัวอื่นใน User PATH ขณะที่ Node อยู่ใน System PATH แล้วยืนยันว่าต้องแก้ System ถึงจะได้ผล
2. **Terminal — ผ่านโดยมีเงื่อนไข (23 ต.ค. 2026):** แอปต้องส่ง environment จาก `CreateEnvironmentBlock` ให้ `wt.exe` เอง ถ้าปล่อยให้สืบทอดจะได้ค่าเก่า แม้ Windows Terminal รันอยู่และได้รับ broadcast แล้ว ดู [RESULT](../spikes/02-terminal/RESULT.md) — เกณฑ์: หลัง Apply เปิด Windows Terminal ด้วย environment ที่คำนวณจาก registry แล้วได้เวอร์ชันใหม่ โดยไม่ต้องรีสตาร์ทแอป และถ้า PowerShell profile แก้ PATH ปุ่ม "ตรวจใน shell" ต้องแสดงความต่างได้
3. **mise — ผ่านโดยมีเงื่อนไข (23 ต.ค. 2026):** Flutter ต้องใช้ vfox backend ดู [RESULT](../spikes/03-mise/RESULT.md) — เกณฑ์: ใช้ mise.exe ที่ pin ไว้กับโฟลเดอร์ข้อมูลแยก ติดตั้งและถอน Temurin, Node, Python, Go และ Flutter ได้ และอ่านผล `mise ls --json` ได้ และถ้าติดตั้งที่ที่เก็บ A แล้วเปลี่ยนเป็น B ต้องยังเห็นและถอนการติดตั้งใน A ได้
4. **Envarly — ผ่าน (23 ต.ค. 2026):** pin ที่ `f0ad0ff` build ได้ และ Apply กับ rollback ทำงานถูกต้องบน registry จริง ทั้ง User และ System registry กลับมาตรงกับไฟล์สำรองทุกบรรทัด แต่พบส่วนที่ต้องทำเพิ่ม 4 ข้อ ดู [RESULT](../spikes/04-envarly/RESULT.md) — เกณฑ์: pin commit แล้ว build ได้ และทดสอบ Apply กับ rollback ของ User และ System PATH จริง
5. **Python — ได้คำตอบแล้ว (23 ต.ค. 2026):** `py` launcher **มองไม่เห็น** Python ที่ mise ติดตั้ง ตรงกับการตัดสินใจ Q16 ที่ให้แสดง `py` เป็นข้อมูลแยก
6. **Uninstaller — ผ่าน (23 ต.ค. 2026):** จับคู่การติดตั้งภายนอกทุกตัวกับรายการ uninstall ได้ ถ้าเป็น MSI ต้องเรียก `msiexec /x` เอง เพราะ UninstallString เป็น `/I` และถ้า InstallLocation ว่าง ให้หาโฟลเดอร์จาก MSI ที่ cache ไว้ ดู [RESULT](../spikes/06-uninstaller/RESULT.md) — เกณฑ์: อ่าน UninstallString ของ Temurin 17 ได้ และระบุได้ว่าการติดตั้งใดเป็นโฟลเดอร์ล้วน
7. **Process — ผ่านโดยมีเงื่อนไข (23 ต.ค. 2026):** Restart Manager จับ java และ Gradle daemon ได้ แต่ shell ที่ cd อยู่ในโฟลเดอร์ต้องตรวจด้วยการลองเปลี่ยนชื่อโฟลเดอร์ ดู [RESULT](../spikes/07-process/RESULT.md) — เกณฑ์: ตรวจหา process ที่รันจากโฟลเดอร์ JDK ได้ ทั้ง Gradle daemon และ Android Studio

เกณฑ์ทดสอบรับงานที่ได้จากผลงานพิสูจน์และการตัดสินใจอยู่ใน [acceptance-criteria.md](acceptance-criteria.md)

| Q27 | การติดตั้งที่มีผลจริง | คำนวณจาก registry ก่อนโหลด profile และแยกคำว่า "ผลใน shell" พร้อมปุ่ม "ตรวจใน shell" |
| Q28 | ถอนหลังเปลี่ยนที่เก็บ | การติดตั้งแต่ละตัวบันทึกที่เก็บของตัวเอง และแอปเรียก mise ด้วยที่เก็บนั้น |
| Q29 | ล้มเหลวหรือถูกยกเลิกกลางทาง | ใช้ตามตารางในส่วนที่ 2 ถ้ายกเลิก uninstaller ให้คงการสลับไว้ |

| Q30 | รายการ PATH ที่ใช้ตัวแปร | ขยายตัวแปรก่อนตัดสินว่าโฟลเดอร์ไม่มีอยู่จริง (เกณฑ์ C-2) |
| Q31 | mise มาถึงเครื่องผู้ใช้อย่างไร | ดาวน์โหลดเวอร์ชันที่ pin ไว้เมื่อผู้ใช้สั่งติดตั้งครั้งแรก ตรวจ SHA256 กับค่าที่ฝังในแอป แล้วเก็บที่ `%LOCALAPPDATA%\Whichcraft\mise\<version>\` ไม่พกมาใน installer (แก้ ADR-0002) |
| Q32 | การเปลี่ยนเวอร์ชัน mise ที่ pin | เปลี่ยนเฉพาะตอนออก Whichcraft รุ่นใหม่ และต้องผ่านเกณฑ์ชุด I, S, R ผู้ใช้อัปเดต mise เองไม่ได้ |

Q25–Q29 มาจากรีวิวเอกสารหลังแยกไฟล์ ผู้ใช้ตอบว่า "ตามแนะนำ" ทุกข้อ Q30 มาจากการสรุปเกณฑ์ทดสอบรับงาน ผู้ใช้รับตามที่เสนอ Q31–Q32 มาจากผลงานพิสูจน์ข้อ 3 ที่พบว่า mise.exe มีขนาด 230 MB ผู้ใช้ตอบว่า "ตามแนะนำ"
