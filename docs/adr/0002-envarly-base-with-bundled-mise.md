# ใช้ Envarly เป็นฐาน และใช้ mise เวอร์ชันที่ pin ไว้สำหรับดาวน์โหลด ติดตั้ง และถอน

ผู้ใช้ขยายขอบเขตรุ่นแรกให้ดาวน์โหลด ติดตั้ง และถอนได้ จึงเลือก fork [Envarly](https://github.com/iray-tno/envarly) เพราะมีระบบแก้ environment ของ Windows อยู่แล้ว และใช้ mise ทำงานดาวน์โหลด ติดตั้ง ถอน และดูรายการเวอร์ชันที่ติดตั้งได้ แอปยังต้องเขียน environment ของ Windows เอง เพราะ mise ไม่เขียน JAVA_HOME หรือ PATH ถาวรลง registry IDE ที่อ่าน JAVA_HOME โดยตรงจึงไม่เห็นการเลือกของ mise

แอปใช้ mise เวอร์ชันที่ pin ไว้เท่านั้น และใช้โฟลเดอร์ข้อมูลกับ config ที่แยกจาก mise ที่ผู้ใช้อาจติดตั้งเอง การติดตั้งที่แอปจัดการจึงเปลี่ยนหรือถูกลบได้จากแอปเท่านั้น ถ้าผู้ใช้ติดตั้ง mise ของตัวเองด้วย การติดตั้งของ mise ตัวนั้นจะแสดงเป็นการติดตั้งภายนอก

**แก้ไข 23 ต.ค. 2026 (Q31, Q32):** แอปไม่พก mise มาใน installer แต่จะดาวน์โหลด mise เวอร์ชันที่ pin ไว้จาก GitHub release ของ mise ในครั้งแรกที่ผู้ใช้สั่งติดตั้งเครื่องมือ ตรวจ SHA256 กับค่าที่ฝังไว้ในแอป แล้วเก็บไว้ที่ `%LOCALAPPDATA%\Whichcraft\mise\<version>\` เหตุผลคือ mise.exe ของ Windows ใหญ่ 230 MB (zip 77 MB) ซึ่งจะทำให้ installer โตจากราว 5 MB เป็นราว 80 MB งานที่ต้องใช้ mise ทุกงานต้องต่อเน็ตอยู่แล้ว ยกเว้นการถอน ซึ่งเกิดได้เฉพาะหลังจากเคยติดตั้งมาก่อน และตอนนั้น mise ถูกโหลดมาแล้ว การโหลดตอนใช้จึงไม่ทำให้ทำอะไรได้น้อยลง เวอร์ชันที่ pin จะเปลี่ยนเฉพาะตอนออก Whichcraft รุ่นใหม่ และต้องผ่านเกณฑ์ทดสอบชุด I, S และ R ก่อน ผู้ใช้อัปเดต mise เองไม่ได้

## Considered Options

- **เขียนตัวดาวน์โหลดเองแยกตามเครื่องมือ:** ต้องดูแลแหล่งดาวน์โหลด checksum และการแตกไฟล์ของทุกเครื่องมือเอง
- **ใช้ [mise_gui](https://github.com/likaia/mise_gui) เป็นฐาน:** ต้องใช้ Dart ^3.11.1 ซึ่งใหม่กว่าที่มีในเครื่อง และยังต้องเพิ่มส่วนเชื่อมกับ Windows ทั้งหมด
- **ใช้ mise ที่ผู้ใช้ติดตั้งเอง:** แชร์ config และโฟลเดอร์กับการใช้งานใน Terminal ทำให้การติดตั้งถูกลบจากนอกแอปได้ และอาจพังเมื่อผู้ใช้อัปเกรด mise
- **พก mise มาใน installer:** ติดตั้งเครื่องมือได้โดยไม่ต้องโหลด mise เพิ่ม แต่ installer ใหญ่ราว 80 MB และผู้ใช้ที่ใช้แค่การสลับของเดิมก็ต้องโหลด mise มาด้วย
- **ให้ผู้ใช้อัปเดต mise เอง:** ทำให้การ pin ไม่มีความหมาย และพฤติกรรมเปลี่ยนโดยไม่ได้ทดสอบ

## Consequences

- mise ไม่มี Git for Windows ใน registry ของตัวเอง ในรุ่นแรก Git จึงสลับได้อย่างเดียว
- งานพิสูจน์ข้อ 3 ผ่านโดยมีเงื่อนไข ([ผล](../../spikes/03-mise/RESULT.md)) Flutter ต้องติดตั้งผ่าน `vfox:jdx/vfox-flutter` เพราะ `http:flutter` แตกไฟล์ read-only บน Windows ไม่ได้ ส่วนขนาด 230 MB ของ mise.exe ทำให้เปลี่ยนเป็นการโหลดตอนใช้ครั้งแรก (ดูหัวข้อแก้ไขด้านบน)
- แอปขึ้นกับการที่ GitHub release ของ mise เวอร์ชันที่ pin ยังเปิดให้โหลดได้ การตรวจ SHA256 ป้องกันไฟล์ถูกแก้ แต่ไม่ช่วยกรณีที่ไฟล์ถูกลบ
- Envarly ที่ `f0ad0ff` build ผ่าน ([ผล](../../spikes/04-envarly/RESULT.md)) แต่ใช้เป็นฐานได้เฉพาะส่วนอ่าน/เขียน registry และ Apply พร้อม rollback ทันทีเมื่อล้มเหลว ส่วนที่ต้องสร้างเอง ได้แก่ บันทึกขั้นตอนลงดิสก์, Undo ที่ย้อนเฉพาะสิ่งที่แอปเปลี่ยน, การเทียบ PATH ทีละรายการ และการขอ UAC เฉพาะตอนเขียน HKLM
