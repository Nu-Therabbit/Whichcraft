# ใช้ Envarly เป็นฐาน และพก mise มาเองสำหรับดาวน์โหลด ติดตั้ง และถอน

ผู้ใช้ขยายขอบเขตรุ่นแรกให้ดาวน์โหลด ติดตั้ง และถอนได้ จึงเลือก fork [Envarly](https://github.com/iray-tno/envarly) เพราะมีระบบแก้ environment ของ Windows อยู่แล้ว และใช้ mise ทำงานดาวน์โหลด ติดตั้ง ถอน และดูรายการเวอร์ชันที่ติดตั้งได้ แอปยังต้องเขียน environment ของ Windows เอง เพราะ mise ไม่เขียน JAVA_HOME หรือ PATH ถาวรลง registry IDE ที่อ่าน JAVA_HOME โดยตรงจึงไม่เห็นการเลือกของ mise

แอปพก mise.exe เวอร์ชันที่ pin ไว้มาเอง และใช้โฟลเดอร์ข้อมูลกับ config ที่แยกจาก mise ที่ผู้ใช้อาจติดตั้งเอง การติดตั้งที่แอปจัดการจึงเปลี่ยนหรือถูกลบได้จากแอปเท่านั้น ถ้าผู้ใช้ติดตั้ง mise ของตัวเองด้วย การติดตั้งของ mise ตัวนั้นจะแสดงเป็นการติดตั้งภายนอก

## Considered Options

- **เขียนตัวดาวน์โหลดเองแยกตามเครื่องมือ:** ต้องดูแลแหล่งดาวน์โหลด checksum และการแตกไฟล์ของทุกเครื่องมือเอง
- **ใช้ [mise_gui](https://github.com/likaia/mise_gui) เป็นฐาน:** ต้องใช้ Dart ^3.11.1 ซึ่งใหม่กว่าที่มีในเครื่อง และยังต้องเพิ่มส่วนเชื่อมกับ Windows ทั้งหมด
- **ใช้ mise ที่ผู้ใช้ติดตั้งเอง:** แชร์ config และโฟลเดอร์กับการใช้งานใน Terminal ทำให้การติดตั้งถูกลบจากนอกแอปได้ และอาจพังเมื่อผู้ใช้อัปเกรด mise

## Consequences

- mise ไม่มี Git for Windows ใน registry ของตัวเอง ในรุ่นแรก Git จึงสลับได้อย่างเดียว
- งานพิสูจน์ข้อ 3 ผ่านโดยมีเงื่อนไข ([ผล](../../spikes/03-mise/RESULT.md)) Flutter ต้องติดตั้งผ่าน `vfox:jdx/vfox-flutter` เพราะ `http:flutter` แตกไฟล์ read-only บน Windows ไม่ได้ และ mise.exe ของ Windows มีขนาด 240 MB ทำให้ตัวติดตั้งของแอปใหญ่ตาม
- Envarly ที่ `f0ad0ff` build ผ่าน ([ผล](../../spikes/04-envarly/RESULT.md)) แต่ใช้เป็นฐานได้เฉพาะส่วนอ่าน/เขียน registry และ Apply พร้อม rollback ทันทีเมื่อล้มเหลว ส่วนที่ต้องสร้างเอง ได้แก่ บันทึกขั้นตอนลงดิสก์, Undo ที่ย้อนเฉพาะสิ่งที่แอปเปลี่ยน, การเทียบ PATH ทีละรายการ และการขอ UAC เฉพาะตอนเขียน HKLM
