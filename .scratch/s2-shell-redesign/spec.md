# S2 desktop shell: tool cards and tool sheet

Status: ready-for-human
Date: 2026-11-02

## Problem Statement

ผู้ใช้ Whichcraft ใช้แอปคู่กับเทอร์มินัลและ IDE เพื่อดูว่า Windows ใช้ Tool Installation ตัวไหน และเปลี่ยนมันอย่างตั้งใจ หน้าเดิมเป็นแถวข้อความกับแผงรายละเอียดแคบๆ ทำให้แยกเครื่องมือด้วยสายตาได้ยาก ต้องเปิดรายละเอียดก่อนถึงจะเห็นเวอร์ชันอื่น และการสลับเวอร์ชันต้องทำหลายขั้นตอน

ผู้ใช้ทดลอง prototype หลายทิศทางแล้วเลือก S2: Zinc cards ที่หัวการ์ดมีสีของเครื่องมือ

หน้าจริงย้ายมาเป็น S2 แล้วใน commit `8de6211` แต่ยังเหลือช่องว่างที่ทำให้เรียกว่าเสร็จไม่ได้: พฤติกรรมใหม่บางส่วนยังไม่มีเทสต์, ยังไม่ได้ตรวจ High Contrast และข้อความแปลที่ยาว, ตัวตรวจในเบราว์เซอร์ของ fixture ยังไม่ได้รันกับหน้าใหม่ และยังมีจุดเล็กน้อยจากรอบตรวจ UI ที่ค้างอยู่

## Solution

แอปมีเมนูซ้ายที่แสดงทุกเครื่องมือพร้อมโลโก้จริงและจำนวนการติดตั้ง หน้า Developer tools แสดงการ์ดของแต่ละเครื่องมือ พร้อมทุกเวอร์ชันที่ติดตั้งอยู่ เวอร์ชันที่เป็น Effective Installation และปุ่ม Use

การเปิดเครื่องมือจะแสดงแผ่นรายละเอียดเต็มพื้นที่ทำงาน โดยเมนูซ้ายยังใช้ได้ ส่วนการรีวิวแผน การติดตั้ง การถอนการติดตั้ง และการลบ Tool Profile เป็น dialog ทุกการเปลี่ยนแปลงยังต้องรีวิวก่อน Apply และ Undo ได้เหมือนเดิม

งานตาม spec นี้คือปิดช่องว่างที่เหลือ โดยไม่เปลี่ยนทิศทางของดีไซน์ ดูรายการที่ยังต้องทำใน Implementation Decisions หัวข้อ "งานที่เหลือ"

## User Stories

### ภาพรวมเครื่องมือ

1. ในฐานะผู้ใช้ ฉันต้องการเห็นเครื่องมือทั้งหมดเป็นการ์ดพร้อมโลโก้จริง เพื่อหาเครื่องมือที่ต้องการได้ทันที
2. ในฐานะผู้ใช้ ฉันต้องการให้แต่ละการ์ดมีสีของเครื่องมือที่ส่วนหัว เพื่อจำเครื่องมือได้โดยไม่ต้องอ่านชื่อ
3. ในฐานะผู้ใช้ ฉันต้องการให้สีของเครื่องมือไม่ไปทับแถวเวอร์ชัน เพื่อให้อ่านเวอร์ชันได้สบาย
4. ในฐานะผู้ใช้ ฉันต้องการเห็นทุกเวอร์ชันที่ติดตั้งบนการ์ด เพื่อไม่ต้องเปิดรายละเอียดก่อน
5. ในฐานะผู้ใช้ ฉันต้องการเห็นว่าเวอร์ชันไหนเป็น Effective Installation ด้วยคำว่า In use ไม่ใช่สีอย่างเดียว เพื่อรู้แน่ว่า process ใหม่จะได้ตัวไหน
6. ในฐานะผู้ใช้ ฉันต้องการเห็นทันทีเมื่อ Selection ไม่ตรงกับ Effective Installation เพื่อรู้ว่ามีอะไรต้องแก้
7. ในฐานะผู้ใช้ ฉันต้องการให้ข้อความใต้หัวหน้าบอกสถานะรวมและชื่อเครื่องมือที่ไม่ตรง เพื่อรู้ว่าควรเริ่มจากตรงไหน
8. ในฐานะผู้ใช้ ฉันต้องการเห็น Unavailable Installation ที่ระบุชัดเจนและกด Use ไม่ได้ เพื่อไม่เลือกการติดตั้งที่ใช้ไม่ได้
9. ในฐานะผู้ใช้ที่มีสองการติดตั้งซึ่งเวอร์ชันและผู้ผลิตเหมือนกัน ฉันต้องการเห็น path ของแต่ละตัว เพื่อแยกออกจากกันได้
10. ในฐานะผู้ใช้ ฉันต้องการกด Use บนการ์ดแล้วเห็นรีวิวแผนเลย เพื่อสลับเวอร์ชันได้เร็ว
11. ในฐานะผู้ใช้ ฉันต้องการค้นหาเครื่องมือด้วยคำค้น เพื่อกรองการ์ดได้
12. ในฐานะผู้ใช้ ฉันต้องการกด Rescan แล้วผลเดิมยังอยู่บนจอ เพื่อไม่เสียตำแหน่งที่กำลังดู
13. ในฐานะผู้ใช้คีย์บอร์ด ฉันต้องการให้โฟกัสไม่หลุดจากปุ่ม Rescan ระหว่างสแกน เพื่อทำงานต่อได้
14. ในฐานะผู้ใช้ ฉันต้องการปุ่ม Retry scan บนการ์ดที่สแกนไม่สำเร็จ เพื่อลองใหม่ได้ตรงจุด
15. ในฐานะผู้ใช้ ฉันต้องการเห็นสถานะกำลังสแกนในการสแกนครั้งแรก เพื่อไม่เข้าใจผิดว่าไม่มีการติดตั้ง
16. ในฐานะผู้ใช้ ฉันต้องการให้การ์ดเครื่องมือที่ไม่มีการติดตั้งมีปุ่ม Install เพื่อเริ่มติดตั้งได้จากตรงนั้น
17. ในฐานะผู้ใช้ Git ฉันต้องการไม่เห็นตัวเลือกติดตั้งหรืออัปเดต Git เพราะแอปสลับ Git ได้อย่างเดียว
18. ในฐานะผู้ใช้ ฉันต้องการเปิดดู Android SDK, MSVC และ Windows SDK แบบ Inventory Only เพื่อดูข้อมูลโดยไม่มีตัวเลือกให้เปลี่ยน

### เมนูซ้าย

19. ในฐานะผู้ใช้ ฉันต้องการเปิดเครื่องมือจากเมนูซ้ายได้ทุกหน้า เพื่อไม่ต้องกลับไปหน้า Developer tools ก่อน
20. ในฐานะผู้ใช้ ฉันต้องการเห็นจำนวนการติดตั้งของแต่ละเครื่องมือในเมนู เพื่อดูภาพรวมได้เร็ว
21. ในฐานะผู้ใช้ ฉันต้องการเห็นจุดเตือนในเมนูเมื่อเครื่องมือไม่ตรงกับ Selection หรือสแกนไม่สำเร็จ เพื่อเห็นปัญหาจากทุกหน้า
22. ในฐานะผู้ใช้ ฉันต้องการพับส่วน Tools ได้ เพื่อให้เมนูสั้นลง
23. ในฐานะผู้ใช้ ฉันต้องการเห็นชื่อเครื่องมือที่เปิดอยู่บนหัวข้อ Tools ตอนที่พับ เพื่อรู้ว่าตัวเองอยู่ตรงไหน
24. ในฐานะผู้ใช้ ฉันต้องการให้แถบเลือกในเมนูอยู่ตรงแถวที่เปิดอยู่เสมอ เพื่อไม่สับสน
25. ในฐานะผู้ใช้ High Contrast ฉันต้องการเห็นว่าแถวไหนถูกเลือก แม้ระบบตัดสีพื้นหลังออก เพื่อใช้เมนูได้

### แผ่นรายละเอียดเครื่องมือ

26. ในฐานะผู้ใช้ ฉันต้องการให้รายละเอียดเต็มพื้นที่ทำงาน เพื่อเห็นข้อมูลครบโดยไม่ต้องเลื่อนในแผงแคบ
27. ในฐานะผู้ใช้ ฉันต้องการสลับไปเครื่องมืออื่นจากเมนูซ้ายโดยไม่ต้องปิดแผ่นก่อน เพื่อเทียบเครื่องมือได้เร็ว
28. ในฐานะผู้ใช้ ฉันต้องการให้เครื่องมือถัดไปเริ่มที่ด้านบนของแผ่น เพื่อไม่ค้างตำแหน่งเดิม
29. ในฐานะผู้ใช้ ฉันต้องการเห็นชื่อเครื่องมือและปุ่มปิดตลอดเวลาที่เลื่อน เพื่อไม่ต้องเลื่อนกลับขึ้นไป
30. ในฐานะผู้ใช้ ฉันต้องการเห็น Effective Installation กับ Selection คู่กัน เพื่อเทียบได้ทันที
31. ในฐานะผู้ใช้ ฉันต้องการเห็นเหตุผลเมื่อ Windows ไม่ใช้ Selection และมีปุ่มแก้ในจุดเดียวกัน เพื่อแก้ได้ทันที
32. ในฐานะผู้ใช้ ฉันต้องการเห็น path เต็มและประเภทผู้ติดตั้งของทุกเวอร์ชัน เพื่อรู้ว่าแอปเป็นเจ้าของการติดตั้งนั้นหรือไม่
33. ในฐานะผู้ใช้ ฉันต้องการเปิดโฟลเดอร์ของการติดตั้งได้ เพื่อตรวจดูไฟล์
34. ในฐานะผู้ใช้โปรแกรมอ่านหน้าจอ ฉันต้องการให้ปุ่ม Uninstall บอกชื่อเวอร์ชัน เพื่อรู้ว่ากำลังจะถอนตัวไหน
35. ในฐานะผู้ใช้ ฉันต้องการเลือกการติดตั้งที่เป็น Effective Installation เป็น Selection ได้เมื่อทั้งสองไม่ตรงกัน เพื่อแก้ความต่างได้ทั้งสองทาง
36. ในฐานะผู้ใช้ ฉันต้องการตรวจ Shell Resolution จากแผ่นนี้ เพื่อดูว่าเทอร์มินัลใหม่ได้ตัวเดียวกับที่คำนวณจาก registry หรือไม่
37. ในฐานะผู้ใช้ ฉันต้องการเปิดเทอร์มินัลจากแผ่นนี้ เพื่อลองใช้งานต่อทันที
38. ในฐานะผู้ใช้ ฉันต้องการเห็น Tool Profile ที่มีเครื่องมือนี้ และ Apply ได้จากตรงนั้น เพื่อไม่ต้องสลับหน้า
39. ในฐานะผู้ใช้ ฉันต้องการติดตั้งเวอร์ชันอื่นและตรวจอัปเดตจากแผ่นนี้ เพื่อจัดการเครื่องมือในที่เดียว
40. ในฐานะผู้ใช้คีย์บอร์ด ฉันต้องการให้โฟกัสเข้าหัวข้อของแผ่นตอนเปิด เพื่ออ่านต่อได้เลย
41. ในฐานะผู้ใช้คีย์บอร์ด ฉันต้องการกด Escape เพื่อปิดแผ่น และให้โฟกัสกลับไปที่ปุ่มที่เปิดมัน เพื่อทำงานต่อจากจุดเดิม
42. ในฐานะผู้ใช้คีย์บอร์ด ฉันต้องการให้ Escape ปิด dialog ก่อนเมื่อมี dialog ซ้อนอยู่ เพื่อไม่ปิดเกินที่ตั้งใจ
43. ในฐานะผู้ใช้ ฉันต้องการกด Developer tools ขณะเปิดแผ่นอยู่แล้วกลับไปหน้าการ์ด เพื่อถอยหนึ่งขั้นได้ง่าย
44. ในฐานะผู้ใช้ ฉันต้องการไปหน้าอื่นแล้วกลับมาเจอแผ่นเดิม เพื่อไม่เสียงานที่ค้างอยู่

### การสลับและ Undo

45. ในฐานะผู้ใช้ ฉันต้องการเห็น diff ของ User และ System environment ใน dialog ก่อน Apply เพื่อรู้ว่าอะไรจะเปลี่ยน
46. ในฐานะผู้ใช้ ฉันต้องการปิดรีวิวโดยไม่มีอะไรถูกเขียน เพื่อยกเลิกได้อย่างปลอดภัย
47. ในฐานะผู้ใช้ ฉันต้องการเห็นข้อผิดพลาดใน dialog ถ้า Apply ไม่สำเร็จหรือแผนหมดอายุ เพื่อไม่พลาดเพราะข้อความไปอยู่ข้างหลัง dialog
48. ในฐานะผู้ใช้ ฉันต้องการให้ dialog ไม่กะพริบเมื่อแผนถูกสร้างใหม่หลังหมดอายุ เพื่อไม่สับสน
49. ในฐานะผู้ใช้ ฉันต้องการเห็นข้อความว่า process ใหม่จะได้เวอร์ชันนั้นเฉพาะเมื่อผลอ่านกลับยืนยันแล้ว เพื่อเชื่อข้อความนั้นได้
50. ในฐานะผู้ใช้ ฉันต้องการได้รับแจ้งเมื่อ Apply สำเร็จแต่ Windows ยังใช้ตัวอื่น เพื่อไม่เข้าใจผิดว่าแก้เสร็จแล้ว
51. ในฐานะผู้ใช้ ฉันต้องการรู้ว่าเทอร์มินัลที่เปิดอยู่ยังใช้ environment เดิม เพื่อเปิดเทอร์มินัลใหม่
52. ในฐานะผู้ใช้ ฉันต้องการกด Undo จากข้อความแจ้งผล เพื่อย้อนกลับได้ทันที
53. ในฐานะผู้ใช้ ฉันต้องการไม่เห็นข้อความของเครื่องมือหนึ่งบนแผ่นของอีกเครื่องมือ เมื่อสลับเครื่องมือระหว่าง Apply เพื่อไม่อ่านผลผิดตัว
54. ในฐานะผู้ใช้ ฉันต้องการเห็นแถวเวอร์ชันใหม่เด่นขึ้นครู่หนึ่งหลังสลับ เพื่อเห็นว่าอะไรเปลี่ยน
55. ในฐานะผู้ใช้ที่ตั้งลดการเคลื่อนไหว ฉันต้องการให้การเปลี่ยนหน้าและแผ่นไม่เลื่อน เพื่อใช้งานได้สบาย

### ติดตั้งและถอนการติดตั้ง

56. ในฐานะผู้ใช้ ฉันต้องการเลือกเครื่องมือและเวอร์ชันใน dialog เดียว เพื่อเปลี่ยนใจได้โดยไม่ต้องปิด
57. ในฐานะผู้ใช้ ฉันต้องการเห็นข้อผิดพลาดของรายการเวอร์ชันและลองใหม่ได้ใน dialog เพื่อแก้ปัญหาได้ตรงจุด
58. ในฐานะผู้ใช้ ฉันต้องการเห็นวิธีถอน สิ่งที่ใช้งานอยู่ และ Tool Profile ที่ได้รับผลกระทบก่อนยืนยัน เพื่อตัดสินใจได้ถูก
59. ในฐานะผู้ใช้ ฉันต้องการให้ปุ่มยืนยันถอนการติดตั้งเป็นสีแดง เพื่อรู้ว่าเป็นการกระทำที่ทำลายข้อมูล

### Tool Profile

60. ในฐานะผู้ใช้ ฉันต้องการเห็น Tool Profile เป็นการ์ดพร้อมโลโก้เครื่องมือ เพื่ออ่านได้เร็ว
61. ในฐานะผู้ใช้ ฉันต้องการไม่เห็นปุ่ม Apply เมื่อ Tool Profile ตรงกับที่ใช้อยู่แล้ว เพื่อไม่กดแล้วไม่มีอะไรเกิดขึ้น

## Implementation Decisions

### สิ่งที่ตัดสินใจแล้วและอยู่ใน `8de6211`

- **Tokens:** ใช้ชื่อ semantic token เดิมเพื่อให้หน้า Environment เดิมเปลี่ยนตาม และเพิ่ม primary กับ destructive เพราะสีข้อความ accent ในธีมมืดสว่างเกินกว่าจะใช้เป็นพื้นปุ่ม เอกสารระบบดีไซน์เป็นแหล่งอ้างอิงของค่าทั้งหมด
- **สีเครื่องมือ:** เป็นตัวตน ไม่ใช่สถานะ ผูกกับ `data-tool` ค่าคงที่ต่อเครื่องมือ ข้อความไม่ใช้สีนี้ และสีจางออกจากมุมขวาบนจนหมดภายในการ์ด
- **เงาโลโก้:** อยู่ในหัวการ์ดเท่านั้น ไม่ทับเวอร์ชันหรือปุ่ม
- **สุขภาพของการ์ด:** model ของภาพรวมมี `scanHealth` แยกจาก `toolHealth` เดิม การสแกนครั้งแรกไม่มีอะไรให้แสดง ส่วนการสแกนซ้ำยังแสดงผลเดิมจนผลใหม่มา ชื่อที่โปรแกรมอ่านหน้าจออ่านยังมาจาก `toolHealth`
- **แผ่นรายละเอียด:** ยังเป็น landmark `complementary` ชื่อ Installation details และอยู่ได้เฉพาะหน้า Developer tools หน้าการ์ดด้านหลังเป็น `inert` ขณะเปิดแผ่น
- **รีวิวแผน:** มี dialog เดียวสำหรับแผนของเครื่องมือและ Tool Profile แผน PATH cleanup ยังอยู่ใน Environment เพราะต้องดูคู่กับสรุปรายการที่ถูกล้าง
- **Use จากการ์ด:** เปิดแผ่นของเครื่องมือนั้นก่อน แล้วรอให้ store ของเครื่องมือตามทัน จึงสร้างแผน เมื่อยกเลิกรีวิวแล้วผู้ใช้จะอยู่ที่แผ่น ไม่ได้กลับไปหน้าการ์ด
- **เลือกเครื่องมือใน dialog ติดตั้ง:** ยังใช้ selected tool ตัวเดียวกับแผ่น แผ่นของเครื่องมือนั้นจึงเปิดอยู่ข้างหลัง dialog ยอมรับพฤติกรรมนี้ในรอบนี้ เพราะการแยกต้องแก้ store ของเครื่องมือ
- **ข้อความหลัง Apply:** ใช้ผลอ่านกลับเป็นตัวตัดสิน และนับเฉพาะ Apply ของแผนเครื่องมือเดียวที่ตรงกับเครื่องมือบนจอ Undo ก็ทำงานเป็น `applying` เหมือนกันแต่ไม่มีแผนบนจอ จึงไม่นับเป็น Apply
- **Shell Resolution:** แสดงผลจาก Check in shell จริงเท่านั้น รายการลำดับ PATH ใน prototype เป็นข้อมูลจำลองและแอปยังไม่มีข้อมูลนี้ จึงไม่นำมาแสดง
- **คำเรียก:** ป้ายบนจอใช้ Selection และ Effective installation ตาม `CONTEXT.md` ไม่ใช้คำว่า active หรือ current
- **สีและธีม:** เก็บใน `localStorage` แบบเดียวกับค่าธีมเดิม และตั้งค่าบนเอกสารก่อน render ครั้งแรกเพื่อไม่ให้สีกะพริบ
- **ฟอนต์:** ใช้ฟอนต์ที่มากับ Windows ไม่โหลดจากเน็ต
- **โลโก้:** Devicon v2.16.0 เก็บในโปรเจกต์ และอยู่ในรายการ Licenses
- **Envarly ในหน้า Licenses:** เป็นการให้เครดิตโปรเจกต์ต้นทางตาม MIT ต้องคงไว้

### งานที่เหลือ

1. **เทสต์พฤติกรรมที่ยังไม่มี:** ตามรายการใน Testing Decisions
2. **ชื่อปุ่ม Uninstall:** ปุ่มในแถวเวอร์ชันต้องบอกผู้ผลิตและเวอร์ชันในชื่อที่อ่านออกเสียง โดยเพิ่มข้อความในทั้ง 6 ภาษา และเปลี่ยนเทสต์เดิมที่จับชื่อ `Uninstall` แบบตรงตัวในแถว ปุ่มยืนยันใน dialog ยังชื่อเดิม
3. **ข้อความซ้ำบนการ์ดว่าง:** การ์ดที่ไม่มีการติดตั้งแสดงทั้ง "No installations found." และ "Nothing installed yet" ต้องเหลือข้อความเดียวที่ส่วนหัว และแถวล่างเหลือเฉพาะปุ่ม Install หรือคำแนะนำให้เพิ่ม Scan Root
4. **เหตุผลที่สแกนไม่สำเร็จ:** ตอนนี้ข้อความอยู่เฉพาะ `title` ของปุ่ม Retry scan จึงเข้าถึงด้วยคีย์บอร์ดไม่ได้ ต้องให้โปรแกรมอ่านหน้าจออ่านได้ โดยไม่แสดงข้อความดิบบนการ์ด เพราะเทสต์เดิมกำหนดว่าข้อความดิบจะหายเมื่อโหลดสำเร็จ และควรแสดงเต็มที่แผ่นรายละเอียด
5. **High Contrast:** ตรวจด้วย `forced-colors` ทุกหน้า แถวที่เลือกในเมนูตอนนี้ขึ้นกับพื้นหลังของแถบเลือกซึ่งจะหายไป จึงต้องมีตัวบอกอื่นที่ใช้ได้ใน `forced-colors` ปุ่ม primary กับ destructive ต้องยังเห็นขอบ และเงาโลโก้ซ่อนได้
6. **ข้อความแปลที่ยาว:** ตรวจ `ru`, `ja` และภาษาที่เหลือที่ 900×600 ทุกหน้า รวมปุ่มในหัวแผ่น แถวตั้งค่าสี และแถบเครื่องมือ ห้ามมี overflow แนวนอนหรือปุ่มทับข้อความ fixture ตอนนี้บังคับภาษาอังกฤษ จึงต้องรับภาษาจากพารามิเตอร์ได้
7. **ตัวตรวจของ fixture:** รันตัวตรวจในเบราว์เซอร์กับหน้าใหม่ และแก้ selector หรือการตรวจที่ล้าสมัย ตอนนี้แก้ selector ไปแล้วหนึ่งจุด แต่ยังไม่เคยรันกับหน้าใหม่

## Testing Decisions

- **เทสต์ที่ดี:** ตรวจสิ่งที่ผู้ใช้เห็นและผลที่เรียกไปยัง API ผ่าน role กับชื่อ ไม่ตรวจ class, โครง DOM หรือ state ภายใน
- **Seam หลัก:** render `DesktopShellApp` ด้วย fake tools runtime แล้วขับด้วย `userEvent` เทสต์พฤติกรรมของ shell ทั้งหมดอยู่ที่ seam นี้ ไม่สร้าง seam ใหม่
- **Prior art:** ชุดเทสต์ `desktopShell*` ตัวอย่างใกล้สุดคือเทสต์สลับเวอร์ชันจากการ์ดและข้อความหลัง Apply ในชุด switch
- **ระดับล่าง:** เทสต์ตรงเฉพาะส่วนที่ไม่ต้องใช้ shell คือ logic ล้วนของ tool overview model และ component `ProfilesSection`
- **เพิ่มเทสต์ที่ seam หลักสำหรับ:**
  - เลือกสี accent แล้วค่าอยู่บนเอกสาร และยังอยู่หลัง render ใหม่
  - เปลี่ยนธีมจาก Settings แล้วปุ่มบนหัวหน้าตรงกัน และกลับกัน
  - Escape ปิดแผ่น และโฟกัสกลับไปที่การ์ด
  - Escape ปิด dialog ก่อนและแผ่นยังอยู่
  - เปิดเครื่องมือจากเมนูซ้ายขณะอยู่หน้าอื่น
  - กด Developer tools ขณะเปิดแผ่นแล้วแผ่นปิด และไปหน้าอื่นแล้วกลับมาแผ่นยังอยู่
  - Rescan ไม่ทำให้ผลเดิมหายและโฟกัสไม่หลุด
  - Use จากการ์ดเมื่อการติดตั้งใช้ไม่ได้แล้วตอนอ่านล่าสุด จะไม่สร้างแผน
  - ปุ่ม Retry scan เรียกสแกนใหม่
  - Apply Tool Profile จากแผ่นแล้วรีวิวเปิดขึ้น
  - เหตุผลที่สแกนไม่สำเร็จเข้าถึงได้ด้วยชื่อที่อ่านออกเสียง
- **การตรวจภาพ:** ใช้ `.scratch/windows-workbench` เท่านั้น ซึ่งใช้ component จริงกับข้อมูลในหน่วยความจำ ตรวจ contrast, overflow และ `forced-colors` ทั้งสองธีม เป็นการตรวจประกอบ ไม่ใช่เทสต์ในชุดหลัก
- **ก่อนปิดงาน:** รัน build, lint และ unit test ทั้งหมด ส่วน `test:storybook` ต้องใช้เบราว์เซอร์ของ Playwright ที่เครื่องนี้ยังไม่มี ถ้ายังรันไม่ได้ให้รายงานว่าไม่ได้รัน อย่าดาวน์โหลดเองโดยไม่ได้ขอ
