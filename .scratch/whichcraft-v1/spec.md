# Whichcraft รุ่นแรก — spec

Status: ready-for-agent

คำศัพท์ใช้ตาม `CONTEXT.md` การตัดสินใจอ้างอิง Q1–Q34 ใน `docs/requirements.md` ADR-0001 ถึง 0004 และเกณฑ์ใน `docs/acceptance-criteria.md`

## Problem Statement

ผู้ใช้เป็นนักพัฒนาบน Windows มีเครื่องมือพัฒนาหลายเวอร์ชันในเครื่อง เช่น Temurin 4 ชุด, Node, Python, Go, Flutter และ Git แต่ละตัวติดตั้งมาด้วยวิธีต่างกัน (MSI, Inno Setup, Python install manager, แตกโฟลเดอร์เอง) การเปลี่ยนว่าจะใช้เวอร์ชันไหนเป็นค่าเริ่มต้นต้องแก้ PATH, JAVA_HOME และตัวแปรอื่นเองใน System Properties ซึ่งมีปัญหาหลายข้อ:

- ไม่รู้ว่าเวอร์ชันไหน "มีผลจริง" รายการใน System PATH (เช่น `C:\Program Files\nodejs`) ชนะ User PATH เสมอ แม้ผู้ใช้จะใส่เวอร์ชันที่ต้องการไว้หน้าสุดของ User PATH แล้ว
- Terminal ที่เปิดอยู่ หรือเปิดจากโปรแกรมที่รันค้างไว้ ยังได้ค่าเก่า
- แก้ผิดแล้วย้อนกลับยาก และ PATH สะสมรายการซ้ำและรายการที่ชี้ไปโฟลเดอร์ที่ไม่มีแล้ว
- การติดตั้งหรือถอนเวอร์ชันใหม่ต้องไปหาตัวติดตั้งของแต่ละผู้จำหน่ายเอง และการถอนอาจค้างเพราะมี Gradle daemon หรือ Terminal ที่ cd อยู่ในโฟลเดอร์ใช้งานอยู่
- ไม่มีวิธีบันทึกชุดเวอร์ชันที่ใช้บ่อย เช่น "งาน Android" แล้วสลับกลับมาใช้ได้ในคลิกเดียว

## Solution

Whichcraft เป็นแอป GUI บน Windows (fork จาก Envarly) ที่ทำสิ่งต่อไปนี้
- **ค้นหา:** หาการติดตั้งเครื่องมือพัฒนาทั้งที่มีอยู่แล้วในเครื่อง (การติดตั้งภายนอก) และที่แอปติดตั้งเอง (การติดตั้งที่แอปจัดการ)
- **แสดงสถานะจริง:** แสดงว่าตัวไหนเป็นการติดตั้งที่มีผลจริงสำหรับ process ใหม่ และตรงกับการเลือกของผู้ใช้หรือไม่
- **เลือก:** ให้ผู้ใช้เลือกการติดตั้งที่ต้องการเป็นค่าเริ่มต้นของ Windows
- **Apply และ Undo:** ดู diff ของ User/System environment ก่อน Apply (ขอ UAC เฉพาะตอนที่ต้องแก้ System) และ Undo ได้โดยไม่ทับสิ่งที่โปรแกรมอื่นแก้ไว้
- **เปิด Terminal:** Terminal ที่เปิดจากแอปได้ environment ที่คำนวณใหม่จาก registry ทันที
- **ติดตั้ง อัปเดต และถอน:** ติดตั้งและอัปเดตเครื่องมือผ่าน mise เวอร์ชันที่ pin ไว้ (แอปโหลดตอนใช้ครั้งแรก) ถอนได้ทั้งการติดตั้งที่แอปจัดการและการติดตั้งภายนอก โดยตรวจก่อนว่ามีโปรแกรมใดใช้อยู่หรือไม่
- **โปรไฟล์:** สร้างโปรไฟล์เครื่องมือที่ระบุบางเครื่องมือแล้ว Apply ได้ในครั้งเดียว
- **ทำความสะอาด PATH:** เสนอให้ลบรายการซ้ำและรายการที่ชี้ไปโฟลเดอร์ที่ไม่มีอยู่

## User Stories

### การค้นหาและการแสดงผล

1. ในฐานะนักพัฒนา ฉันอยากเห็นการติดตั้งทุกชุดของ Java, Node.js, Python, Go, Flutter และ Git ในเครื่องเมื่อเปิดแอปครั้งแรก เพื่อจะได้รู้ว่ามีอะไรอยู่แล้วบ้าง โดยไม่ต้องไล่หาเอง
2. ในฐานะนักพัฒนา ฉันอยากให้แอปแสดงผู้จำหน่ายและเวอร์ชันเต็มของ JDK แต่ละชุด เช่น Eclipse Adoptium 21.0.12.1 เพื่อแยก JDK ที่เวอร์ชันใกล้เคียงกันออกจากกันได้
3. ในฐานะนักพัฒนา ฉันอยากให้เวอร์ชันเดียวกันที่อยู่ต่างตำแหน่งแสดงเป็นการติดตั้งแยกกัน เพื่อจะได้เลือกได้ว่าจะใช้ชุดไหน
4. ในฐานะนักพัฒนา ฉันอยากเพิ่มโฟลเดอร์ค้นหาเองได้ เช่น `E:\Dev` เพื่อให้แอปเจอเครื่องมือที่ฉันแตกไฟล์ไว้เอง
5. ในฐานะนักพัฒนา ฉันไม่อยากให้แอปสแกนทุกไดรฟ์เอง เพื่อจะได้ไม่เสียเวลาและไม่ไปแตะโฟลเดอร์ที่ไม่เกี่ยวข้อง
6. ในฐานะนักพัฒนา ฉันอยากให้การติดตั้งที่โฟลเดอร์ถูกย้ายหรือลบไป แสดงเป็น "ใช้งานไม่ได้" แทนที่จะหายไปเฉย ๆ เพื่อจะได้รู้ว่าโปรไฟล์หรือการเลือกของฉันกำลังอ้างถึงของที่ไม่มีแล้ว
7. ในฐานะนักพัฒนา ฉันอยากเห็นว่าการติดตั้งแต่ละชุดมาจากไหน (MSI, Inno Setup, Python install manager, JetBrains Toolbox, โฟลเดอร์ล้วน หรือแอปติดตั้งเอง) เพื่อจะได้เข้าใจว่าใครเป็นเจ้าของไฟล์
8. ในฐานะนักพัฒนา Android ฉันอยากเห็นรายการ Android SDK platforms, build tools, NDK และ MSVC แบบดูอย่างเดียว เพื่อจะได้รู้ภาพรวมของเครื่องในที่เดียว
9. ในฐานะนักพัฒนา ฉันอยากเห็นว่าเครื่องมือแต่ละตัวมีการติดตั้งไหนที่มีผลจริงสำหรับ process ใหม่ เพื่อจะได้รู้ว่าพิมพ์ `node` ใน Terminal ใหม่แล้วจะได้ตัวไหน
10. ในฐานะนักพัฒนา ฉันอยากให้แอปบอกเมื่อการติดตั้งที่มีผลจริงไม่ตรงกับการเลือกของฉัน และแสดงสาเหตุ เช่น มีรายการใน System PATH บังอยู่ เพื่อจะได้แก้ถูกจุด
11. ในฐานะนักพัฒนา ฉันอยากให้สถานะที่แสดงอัปเดตตามจริง เมื่อมีโปรแกรมอื่นหรือตัวฉันเองไปแก้ environment นอกแอป เพื่อจะได้ไม่เชื่อข้อมูลเก่า
12. ในฐานะนักพัฒนา ฉันอยากกด "ตรวจใน shell" เพื่อดูว่า PowerShell หรือ cmd ที่โหลด profile แล้วเรียกเครื่องมือตัวไหน เพื่อจะได้เจอกรณีที่ profile ของฉันแก้ PATH ทับ
13. ในฐานะนักพัฒนา Python ฉันอยากเห็นว่า `py` launcher และ Microsoft Store stub จะเรียก Python ตัวไหน แยกจาก `python` ใน PATH เพื่อจะได้ไม่สับสนว่าทำไมสองคำสั่งได้คนละเวอร์ชัน

### การเลือกและ Apply

14. ในฐานะนักพัฒนา ฉันอยากเลือกการติดตั้งที่ต้องการเป็นค่าเริ่มต้นของ Windows ทีละเครื่องมือ เพื่อจะได้เปลี่ยนเฉพาะสิ่งที่ต้องการ
15. ในฐานะนักพัฒนา ฉันอยากเห็น diff ของ User และ System environment แยกกันก่อน Apply เพื่อจะได้รู้ว่าแอปจะเปลี่ยนอะไรบ้าง
16. ในฐานะนักพัฒนา ฉันอยากให้แอปเสนอให้เอารายการที่บังอยู่ออกจาก System PATH เมื่อตัวที่ฉันเลือกถูกบัง เพื่อให้การเลือกมีผลจริง
17. ในฐานะนักพัฒนา ฉันอยากให้แอปเตือนว่าการแก้ System PATH กระทบผู้ใช้ทุกคนในเครื่อง ก่อนขอ UAC เพื่อจะได้ตัดสินใจได้ถูก
18. ในฐานะนักพัฒนา ฉันอยากให้แอปขอ UAC เฉพาะตอนที่ต้องเขียน System เท่านั้น เพื่อจะได้ไม่ต้องรันทั้งแอปแบบ admin
19. ในฐานะนักพัฒนา ฉันอยากให้พาธที่อยู่ในพื้นที่ของผู้ใช้ เช่น `%LOCALAPPDATA%` ไม่ถูกเขียนลง System PATH เพื่อไม่ให้ผู้ใช้คนอื่นได้พาธที่เข้าไม่ได้
20. ในฐานะนักพัฒนา ฉันอยากให้ถ้ากดยกเลิก UAC แล้วไม่มีอะไรถูกเขียนเลย รวมถึงส่วน User เพื่อไม่ให้ environment อยู่ในสภาพครึ่ง ๆ กลาง ๆ
21. ในฐานะนักพัฒนา ฉันอยากให้ถ้า Apply ล้มเหลวกลางทาง แอปย้อนสิ่งที่เขียนไปแล้วกลับทั้งหมด และรายงานรายการที่ย้อนไม่ได้ เพื่อจะได้รู้สถานะที่แน่นอน
22. ในฐานะนักพัฒนา ฉันอยากให้ถ้าแอปปิดหรือ crash กลาง Apply เปิดใหม่แล้วแอปบอกสถานะจริง และเสนอให้ทำต่อหรือย้อนกลับ เพื่อไม่ให้ environment เสียแบบไม่มีใครรู้
23. ในฐานะนักพัฒนา ฉันอยากให้ JAVA_HOME, GOROOT และ PATH ชี้ไปโฟลเดอร์เวอร์ชันจริง ไม่ใช่ junction หรือ shims เพื่อให้ IDE ที่อ่าน JAVA_HOME ตรง ๆ ได้ค่าที่ถูกต้อง
24. ในฐานะนักพัฒนา ฉันอยากให้ตัวแปรที่เป็นชนิด `REG_EXPAND_SZ` ยังเป็นชนิดเดิมหลัง Apply เพื่อให้รายการอย่าง `%USERPROFILE%\go\bin` ยังขยายค่าได้
25. ในฐานะนักพัฒนาที่ใช้บัญชี admin แบบ UAC ฉันอยากให้ส่วน User ถูกเขียนลง HKCU ของบัญชีที่ฉันใช้งาน ไม่ใช่ของ process ที่ elevate เพื่อไม่ให้ค่าไปผิดบัญชี
26. ในฐานะนักพัฒนา ฉันอยากให้แอปแจ้งชัด ๆ ว่าโปรแกรมที่เปิดอยู่แล้ว และ IDE ที่ตั้ง SDK เอง จะไม่เปลี่ยนตาม เพื่อจะได้ไม่คาดหวังผิด

### Undo

27. ในฐานะนักพัฒนา ฉันอยากกด Undo การ Apply ล่าสุดได้ เพื่อแก้ตัวเองเมื่อเลือกผิด
28. ในฐานะนักพัฒนา ฉันอยากให้ Undo ย้อนเฉพาะสิ่งที่แอปเปลี่ยน และเก็บรายการ PATH ที่โปรแกรมอื่นเพิ่มเข้ามาภายหลังไว้ เพื่อไม่ให้ตัวติดตั้งตัวอื่นเสีย
29. ในฐานะนักพัฒนา ฉันอยากให้แอปแจ้ง conflict และให้ฉันเลือก เมื่อค่าที่แอปเคยเขียนถูกโปรแกรมอื่นแก้ทับไปแล้ว เพื่อไม่ให้แอปเขียนทับโดยไม่รู้ตัว

### Terminal

30. ในฐานะนักพัฒนา ฉันอยากกดปุ่มเปิด Terminal แล้วได้เวอร์ชันใหม่ทันทีโดยไม่ต้องรีสตาร์ทแอปหรือ Windows Terminal เพื่อจะได้ทดลองหลังสลับได้เลย
31. ในฐานะนักพัฒนา ฉันอยากตั้งได้ว่าจะเปิดด้วย Windows Terminal, PowerShell หรือ cmd เพื่อใช้ shell ที่ถนัด
32. ในฐานะนักพัฒนา ฉันอยากให้พาธที่มีอักขระพิเศษ เช่น `;` ไม่ทำให้ Windows Terminal ตัดคำสั่งผิด เพื่อให้ปุ่มเปิด Terminal ใช้ได้กับทุกโฟลเดอร์

### การติดตั้งและอัปเดต

33. ในฐานะนักพัฒนา ฉันอยากติดตั้ง Temurin, Node.js, Python, Go และ Flutter เวอร์ชันที่ต้องการจากในแอป เพื่อจะได้ไม่ต้องไปหาตัวติดตั้งของแต่ละผู้จำหน่าย
34. ในฐานะนักพัฒนา ฉันอยากเห็นรายการเวอร์ชันที่ติดตั้งได้ พร้อมขนาดดาวน์โหลดและพื้นที่ที่จะใช้ ก่อนกดติดตั้ง เพื่อจะได้เช็กพื้นที่ดิสก์ก่อน
35. ในฐานะนักพัฒนา ฉันอยากเลือกที่เก็บการติดตั้งตอนติดตั้งครั้งแรก (ค่าเริ่มต้นคือ `%LOCALAPPDATA%\Whichcraft\installs`) เพื่อจะได้เก็บไว้ในไดรฟ์ที่มีที่ว่าง
36. ในฐานะนักพัฒนา ฉันอยากเปลี่ยนที่เก็บภายหลังได้ โดยการติดตั้งเดิมยังอยู่ที่เดิมและยังถอนได้ เพื่อไม่ต้องย้ายไฟล์ใหญ่
37. ในฐานะนักพัฒนา ฉันอยากให้การติดตั้งเครื่องมือไม่ไปแก้ PATH หรือ config ใด ๆ จนกว่าฉันจะเลือกใช้ เพื่อจะได้ติดตั้งเตรียมไว้ก่อนได้
38. ในฐานะนักพัฒนาที่ใช้ mise ของตัวเองด้วย ฉันไม่อยากให้แอปอ่านหรือแก้ config และการติดตั้งของ mise ตัวนั้น เพื่อให้ทั้งสองระบบไม่ชนกัน
39. ในฐานะผู้ใช้ใหม่ ฉันอยากให้ installer ของ Whichcraft มีขนาดเล็ก และให้แอปโหลด mise เฉพาะตอนที่ฉันสั่งติดตั้งเครื่องมือครั้งแรก พร้อมแจ้งขนาดก่อน เพื่อไม่ต้องโหลดของที่อาจไม่ได้ใช้
40. ในฐานะผู้ใช้ ฉันอยากให้แอปตรวจ hash ของ mise ที่โหลดมา และปฏิเสธถ้าไม่ตรง เพื่อป้องกันไฟล์ถูกแก้ระหว่างทาง
41. ในฐานะผู้ใช้ที่ออฟไลน์ ฉันอยากให้การค้นหา สลับ Apply และ Undo ยังใช้ได้ แม้ยังโหลด mise ไม่ได้ เพื่อให้งานหลักของแอปไม่ขึ้นกับเน็ต
42. ในฐานะนักพัฒนา ฉันอยากให้การดาวน์โหลดที่ล้มเหลวหรือถูกยกเลิกไม่ทิ้งไฟล์ค้างไว้ในที่เก็บ เพื่อไม่ให้แอปเข้าใจผิดว่าติดตั้งครบแล้ว
43. ในฐานะนักพัฒนา Flutter ฉันอยากติดตั้ง Flutter ได้สำเร็จ แม้ zip ของ Flutter จะมีไฟล์ read-only ใน `.git` เพื่อจะได้ไม่เจอ "Access is denied"
44. ในฐานะนักพัฒนา ฉันอยากให้ปลั๊กอินที่ใช้ติดตั้ง Flutter ถูก pin ไว้ที่ commit ที่ทดสอบแล้ว เพื่อให้ติดตั้งได้ผลเหมือนเดิมทุกครั้ง

## Implementation Decisions

### สถาปัตยกรรม

- **ฐานโค้ด:** fork Envarly ที่ commit `f0ad0ff67508bb55091b46bba524667984531350` (Tauri v2, React/TypeScript, Rust) ใช้ส่วนอ่านและเขียน registry, การ Apply ที่อ่านค่ากลับมาตรวจ และการ rollback เมื่อล้มเหลวของ Envarly ต่อ (ADR-0002)
- **Whichcraft core:** โมดูลใหม่ฝั่ง Rust เป็น API ระดับโดเมนที่ Tauri command เรียกใช้ ไม่มีการพึ่ง Windows โดยตรง ทุกอย่างผ่าน port ต่อไปนี้
  - **EnvBackend** (มีอยู่แล้วใน Envarly): อ่านและเขียน User/System/OtherUser environment และ broadcast ส่วนการเขียน System ต้องย้ายไปทำใน process ตัวช่วยที่ elevate ผ่าน UAC เฉพาะครั้งนั้น แทน `restart_as_admin` ของ Envarly ส่วน HKCU ให้ process ปกติเป็นคนเขียนเสมอ
  - **EnvironmentResolver:** สร้าง environment แบบที่ process ใหม่จะได้ (CreateEnvironmentBlock ไม่สืบทอด) และหาการติดตั้งที่มีผลจริง โดยเรียง System ก่อน User แล้วหาตัวแรกที่ชนะ ไม่ได้แค่ดูว่ามีพาธอยู่ใน PATH
  - **InstallationProbe:** อ่านไฟล์ในโฟลเดอร์เพื่อยืนยันรากการติดตั้ง ผู้จำหน่าย และเวอร์ชัน
    - Java: `release` (`IMPLEMENTOR`, `JAVA_VERSION`) + `bin\java.exe`
    - Node: `node.exe` ที่ราก
    - Go: `VERSION` + `bin\go.exe`
    - Python: `python.exe` + `Lib`
    - Flutter: `bin\flutter.bat` + `bin\cache\flutter.version.json`
    - ข้าม junction และ symlink เสมอ
  - **InstallerCatalog:** อ่านรายการ uninstall จาก HKLM, HKLM WOW6432Node และ HKCU แล้วจับคู่กับการติดตั้ง ถ้า InstallLocation ว่าง ให้หาโฟลเดอร์จาก MSI ที่ Windows cache ไว้ (หา component ของไฟล์หลักในตาราง File และ Component แล้วเรียก component path) และจัดชนิดของตัวติดตั้งเป็น MSI, Inno Setup, Python install manager, "มีเครื่องมืออื่นดูแล" (มีรายการแต่ไม่มี UninstallString) และโฟลเดอร์ล้วน
  - **ToolManager:** ตัวเรียก mise ที่ pin ไว้
    - แอปโหลด mise ตอนใช้ครั้งแรก ตรวจ SHA256 กับค่าที่ฝังในแอป แล้วเก็บแยกตามเวอร์ชัน
    - ทุกคำสั่งตั้ง `MISE_DATA_DIR`, `MISE_CACHE_DIR`, `MISE_STATE_DIR`, `MISE_CONFIG_DIR` และ `MISE_GLOBAL_CONFIG_FILE` ให้ชี้ไปที่เก็บการติดตั้งที่กำลังทำงานด้วย
    - ใช้เฉพาะ `install`, `uninstall`, `ls --json` และ `ls-remote --json` ไม่ใช้ `use` และไม่ใช้ shims
    - Flutter ใช้ backend `vfox:jdx/vfox-flutter` และติดตั้งปลั๊กอินด้วย SHA เต็มที่ pin ไว้ก่อนใช้ครั้งแรก ปิดการอัปเดตปลั๊กอินอัตโนมัติ
    - หลังอัปเดต Whichcraft ให้โหลด mise ตัวใหม่เบื้องหลัง ระหว่างรอใช้ตัวเก่าได้เฉพาะถอนและดูรายการ
  - **UsageProbe:** ตรวจว่ามีโปรแกรมใดใช้การติดตั้งอยู่ ด้วย Restart Manager (`RmGetList`) กับไฟล์หลักของการติดตั้ง ร่วมกับดูพาธของ exe จาก WMI และลองเปลี่ยนชื่อโฟลเดอร์ไปและกลับ เพื่อจับ shell ที่ cd ค้างอยู่
  - **Uninstaller:** สั่งถอน
    - MSI: `msiexec /x {ProductCode}` เสมอ ไม่ใช้ UninstallString ที่เป็น `/I`
    - ชนิดอื่น: ใช้ UninstallString ตามที่ลงทะเบียน และเปิดแบบปกติ ไม่ silent
    - โฟลเดอร์ล้วน: ย้ายไป Recycle Bin
  - **Journal:** บันทึกขั้นตอนของ Apply, Undo, ติดตั้ง และถอนลงดิสก์**ก่อน**เริ่มแตะระบบ ใช้กู้คืนเมื่อแอป crash
  - **TerminalLauncher:** เปิด Windows Terminal, PowerShell หรือ cmd ด้วย environment จาก EnvironmentResolver และ escape `;` สำหรับ `wt.exe`
  - **ShellProbe:** รัน shell ที่ตั้งไว้พร้อม profile แล้วถาม `Get-Command` (หรือ `where` ใน cmd) สำหรับปุ่ม "ตรวจใน shell"

### โมเดลและพฤติกรรม

- **การติดตั้งเครื่องมือ** มีตัวระบุที่คงที่ (เครื่องมือ + ผู้จำหน่าย + เวอร์ชันเต็ม + รากการติดตั้ง) แยกเป็นการติดตั้งภายนอกกับการติดตั้งที่แอปจัดการ และการติดตั้งที่แอปจัดการแต่ละชุดบันทึกที่เก็บของตัวเองไว้
- **การเลือก** เก็บแยกจาก**การติดตั้งที่มีผลจริง** แอปไม่เก็บการติดตั้งที่มีผลจริงไว้ แต่คำนวณใหม่ทุกครั้งที่แสดง
- **แผน Apply (plan):** core สร้างแผนจากการเลือกหรือโปรไฟล์ แผนประกอบด้วยรายการเปลี่ยนแยก User/System, รายการ System ที่ต้องเอาออกเพราะบังอยู่, คำเตือน และบอกว่าต้องใช้ UAC หรือไม่ UI แสดงแผนเป็น diff
- **กฎของพาธ (ADR-0004):** พาธในพื้นที่ของผู้ใช้เขียนลง User เท่านั้น ถ้ามีรายการ System บังอยู่ ให้เสนอเอารายการนั้นออก ไม่เพิ่มพาธของผู้ใช้ลง System
- **ความเป็นหนึ่งเดียวของ Apply:** ตรวจทุกการติดตั้งในแผนก่อนเริ่ม ถ้า UAC ถูกยกเลิก ให้ยกเลิกทั้งแผน ถ้าเขียนสำเร็จบางรายการแล้วล้มเหลว ให้ย้อนรายการที่เขียนไปแล้ว
- **แผนต้องไม่เก่า:** แผนเก็บค่าของทุกตัวแปรที่จะแตะไว้ ณ ตอนสร้างแผน ก่อนเขียน (และอีกครั้งหลังได้ UAC) ให้อ่านค่าปัจจุบันมาเทียบ ถ้ามีตัวใดเปลี่ยนไปแล้ว เช่น โปรแกรมอื่นเพิ่มรายการ PATH ระหว่างที่ผู้ใช้ดู diff หรือรอ UAC ให้ไม่เขียนอะไรเลย สร้างแผนและ diff ใหม่จากค่าปัจจุบัน แล้วให้ผู้ใช้ยืนยันอีกครั้ง การ Apply ของ Envarly ตรวจค่ากับตอนที่เริ่ม Apply เท่านั้น ไม่ได้ตรวจกับตอนสร้างแผน จึงต้องเพิ่มส่วนนี้
- **Undo:** อ้างอิงบันทึกขั้นตอนของ Apply ครั้งนั้น ย้อนเฉพาะรายการที่แอปเปลี่ยน
  - ตัวแปรที่เป็นรายการ (PATH และตัวแปรที่คั่นด้วย `;`) เทียบทีละรายการ
  - ตัวแปรเดี่ยวเทียบทั้งค่า ถ้าค่าปัจจุบันไม่ตรงกับที่แอปเขียนไว้ ให้เป็น conflict
- **โปรไฟล์:** เป็นชุดการเลือกบางส่วน อ้างถึงด้วยผู้จำหน่าย + เวอร์ชันเต็ม และจำรากการติดตั้งที่ผู้ใช้เลือกไว้เป็นตัวแรกที่จะใช้ ไม่มีสถานะ "โปรไฟล์ที่ใช้อยู่" มีแต่สถานะ "ตรงหรือไม่ตรง" ที่คำนวณจากการติดตั้งที่มีผลจริง
- **การอัปเดต** ประกอบจากขั้นที่มีอยู่แล้ว: ติดตั้ง → แผน Apply สลับไปตัวใหม่ → เสนอถอนตัวเก่า และเสนอให้โปรไฟล์เปลี่ยนไปอ้างตัวใหม่
- **การถอนตัวที่ใช้อยู่:** ต้องได้ตัวแทนก่อน แล้ว Apply การสลับ จากนั้นตรวจว่ามีโปรแกรมใช้อยู่หรือไม่ แล้วจึงถอน สุดท้ายสแกนใหม่เพื่อยืนยันว่าโฟลเดอร์หายไปแล้ว
- **เงื่อนไขก่อนย้ายโฟลเดอร์ล้วนไป Recycle Bin (Q26):** ต้องผ่านทั้ง 5 ข้อ
  1. เป็นรากการติดตั้งจริง
  2. ไม่ใช่รากไดรฟ์ โปรไฟล์ผู้ใช้ โฟลเดอร์ค้นหา โฟลเดอร์ Windows หรือราก Program Files
  3. ข้างในไม่มีการติดตั้งอื่น
  4. ไม่ใช่ junction หรือ symlink
  5. ไม่มีโปรแกรมใช้อยู่
- **ทำความสะอาด PATH:** ขยายตัวแปรก่อนตัดสินว่ารายการชี้ไปโฟลเดอร์ที่ไม่มีอยู่ และทำผ่านแผนและ Undo เหมือน Apply
- **UI:** ต่อจาก React ของ Envarly หน้าจอหลักใหม่คือ
  - รายการเครื่องมือและการติดตั้ง
  - แผนและ diff ก่อน Apply
  - ติดตั้งและถอน
  - โปรไฟล์
  - ตรวจใน shell
  - การตั้งค่า: Terminal, ที่เก็บ และโฟลเดอร์ค้นหา
  - หน้าจอข้อจำกัด

  ฟีเจอร์ของ Envarly ที่ไม่เกี่ยวข้อง (export DSC/Ansible, secret detection ฯลฯ) จะเก็บไว้หรือซ่อนก็ได้ แต่ห้ามขวางขั้นตอนหลัก

## Testing Decisions

- **การทดสอบที่ดี:** ทดสอบพฤติกรรมที่มองเห็นจากภายนอกผ่าน API ของ Whichcraft core เท่านั้น เช่น สั่ง plan, apply, undo, install หรือ uninstall แล้วตรวจสถานะของ port ปลอมกับผลที่ API คืนมา ไม่ทดสอบฟังก์ชันภายในหรือลำดับการเรียกที่ไม่ได้ส่งผลให้เห็น
- **Seam หลัก: API ของ Whichcraft core กับ port ปลอมในหน่วยความจำ**
  - ต่อยอดจาก `MemBackend` ของ Envarly ซึ่งมี test ของ rollback, conflict และ OtherUser อยู่แล้วราว 120 ข้อ เป็นต้นแบบให้ดู
  - เพิ่มของปลอมสำหรับ port ใหม่ทุกตัว ของปลอมต้องจำลองสิ่งที่งานพิสูจน์พบด้วย ได้แก่ System มาก่อน User, MSI ที่ UninstallString เป็น `/I` และ InstallLocation ว่าง, junction ของ mise, การ rename ที่ถูกล็อก, UAC ที่ถูกยกเลิก และ mise ที่ hash ไม่ตรง
  - เกณฑ์ชุด D, E (ยกเว้นการรัน shell จริง), A, U, I (ยกเว้นการโหลดจริง), S, R, P, F และ C ต้องมี test ที่ seam นี้
- **Seam รอง: adapter contract tests กับ Windows จริง**
  - เปิดใช้เอง ไม่รันใน CI ปกติ เพราะแก้ registry จริงและต้องกด UAC
  - ทำตามแบบงานพิสูจน์ใน `spikes/`: สำรอง registry ก่อนทุกชุด ใช้ตัวแปรทดสอบ และเทียบ registry กับไฟล์สำรองหลังจบ
  - ครอบคลุม EnvBackend (HKCU/HKLM จริง), EnvironmentResolver, ToolManager (mise จริงในที่เก็บแยก), InstallerCatalog (อ่านอย่างเดียว), UsageProbe (สร้าง process จำลองเอง) และ TerminalLauncher
- **UI:** ใช้ vitest และ Testing Library ตามที่ Envarly มีอยู่ (hooks และ components มี `*.test.ts(x)` อยู่แล้ว) ทดสอบหน้าจอใหม่โดยปลอม API ของ Tauri แบบเดียวกับ `api.test.ts`
- **ตรวจด้วยมือบนเครื่องอื่น:** เกณฑ์ X-1 ถึง X-4 ใน acceptance-criteria ทดสอบบนเครื่องนี้ไม่ได้

## Out of Scope

- **การแยกเวอร์ชันต่อโปรเจกต์** หรือหลาย environment ที่ทำงานพร้อมกัน (ADR-0001)
- **ส่งออกและนำเข้าโปรไฟล์** ข้ามเครื่อง (Q20)
- **การติดตั้งเพิ่มเติม:**
  - ติดตั้ง Git ผ่านแอป (Q14)
  - JDK จากผู้จำหน่ายอื่นนอกจาก Temurin
  - ติดตั้ง Android SDK/NDK และ MSVC (แสดงข้อมูลอย่างเดียว)
- **ที่เก็บแบบทั้งเครื่อง** ที่ ProgramData และการรองรับหลายผู้ใช้ (ADR-0004)
- **การจัดการ shell เพิ่มเติม:**
  - ตั้ง `PY_PYTHON` หรือจัดการ `py` launcher และ Microsoft Store stub (Q16)
  - เปลี่ยน environment ของโปรแกรมที่เปิดอยู่แล้ว หรือแท็บที่ผู้ใช้เปิดเองในหน้าต่าง Windows Terminal เดิม
- **การแทรกแซงโปรแกรมของผู้ใช้:** kill process ของผู้ใช้ และถอนแบบ silent
- **การจัดการ mise:** ให้ผู้ใช้อัปเดต mise เอง และใช้ mise ของผู้ใช้ (Q32, Q13)

## Further Notes

- **ข้อจำกัดที่รู้แล้วจากงานพิสูจน์:**
  - ปลั๊กอินแบบ `http:flutter` ของ mise ล้มเหลวกับไฟล์ read-only
  - `mise ls --json` ไม่มีผู้จำหน่าย และชื่อเวอร์ชันของ Java ไม่ตรงกับเวอร์ชันจริง
  - junction ของ mise เก็บพาธเต็ม จึงเสียเมื่อย้ายที่เก็บ
  - `envarly import` พิมพ์ค่า PATH ทั้งค่าออก stdout ห้ามเก็บ output นี้ลง log
- **ยังไม่ได้ตรวจ:** mise จะอัปเดตปลั๊กอินเองระหว่าง `install` หรือไม่ ต้องปิดด้วยการตั้งค่า และทดสอบตามเกณฑ์ I-17
- **ความเสี่ยงภายนอก:** แอปขึ้นกับการที่ GitHub release ของ mise เวอร์ชันที่ pin ยังเปิดให้โหลดได้
- **ลำดับที่แนะนำ:**

  2. ทำ Whichcraft core พร้อม port ปลอม

  4. ทำ Terminal
  5. ทำการค้นหาและ InstallerCatalog
  6. ทำ ToolManager
  7. ทำการถอน

  9. ทำทำความสะอาด PATH
  10. ทำ UI
